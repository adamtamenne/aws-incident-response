# IAM Identity Containment

Quarantines a compromised IAM user or role by deactivating credentials, revoking active sessions, and attaching explicit deny policies.

## What It Does

The script auto-detects whether the target is an IAM user or role, then applies the appropriate containment steps.

### IAM User Containment

1. Captures current state (access keys, policies, groups, MFA, console access)
2. Deactivates all access keys
3. Deletes the login profile (revokes console access)
4. Attaches an explicit deny-all inline policy
5. Attaches a session revocation policy (denies all actions for tokens issued before containment time)

### IAM Role Containment

1. Captures current state (policies, trust policy, instance profiles)
2. Attaches an explicit deny-all inline policy
3. Attaches a session revocation policy (invalidates existing STS tokens)
4. Detaches the role from all instance profiles

Both paths produce a JSON containment report with a record of everything captured and changed.

## Usage

```bash
# Contain a compromised IAM user
./quarantine-iam-identity.sh compromised-user-name

# Contain a compromised IAM role
./quarantine-iam-identity.sh compromised-role-name
```

## Why Two Deny Policies?

The deny-all policy is the immediate containment: it blocks all API actions. The session revocation policy uses `aws:TokenIssueTime` to deny actions from tokens issued before the containment timestamp.

During un-containment, you remove the deny-all first but keep the session revocation policy. This ensures any pre-compromise STS tokens that haven't expired yet remain blocked, while new tokens (issued after containment) work normally.

## Un-containment

After investigation, remove the containment policies:

```bash
# For a user
aws iam delete-user-policy --user-name <name> --policy-name <Containment-DenyAll-...>
aws iam delete-user-policy --user-name <name> --policy-name <RevokeOlderSessions-...>

# For a role
aws iam delete-role-policy --role-name <name> --policy-name <Containment-DenyAll-...>
aws iam delete-role-policy --role-name <name> --policy-name <RevokeOlderSessions-...>
```

The exact policy names are in the JSON containment report generated by the script.

## Prerequisites

- AWS CLI configured with credentials that have IAM permissions
- Bash 4+

## Required IAM Permissions

The identity running this script needs:

- `iam:GetUser`, `iam:GetRole`
- `iam:ListAccessKeys`, `iam:UpdateAccessKey`
- `iam:GetLoginProfile`, `iam:DeleteLoginProfile`
- `iam:ListAttachedUserPolicies`, `iam:ListAttachedRolePolicies`
- `iam:ListUserPolicies`, `iam:ListRolePolicies`
- `iam:PutUserPolicy`, `iam:PutRolePolicy`
- `iam:ListGroupsForUser`
- `iam:ListMFADevices`
- `iam:ListInstanceProfilesForRole`, `iam:RemoveRoleFromInstanceProfile`
